## The GitHub test as a concrete acceptance-feedback example

The user report was not an evaluator case label: repositories were missing from listings, a repository lookup appeared empty, and the reporter believed they had access. Uday supplied the symptom, checked the output, found relevant Composio documentation and asked why that explanation was not developed. The investigation could propose generic authorization or account-context explanations, but it had no shared KB records and no independently observed execution telemetry for the complaint.

That exchange improved the specification in two ways. Custom incidents needed an honest statement of available information, and KB-derived troubleshooting needed to remain distinguishable from incident-backed findings. Uday's subsequent fallback-policy instruction made that priority explicit. This is a directly evidenced example of domain feedback changing the product's behavior and stated limitations.
